# Контракт бейджей exteraGram

## Источник

Контракт взят из исходников exteraGram:

- `ApiClient.kt`: `BASE_URL = "https://api.exteragram.app/api/v1/"`;
- `ApiService.kt`: `GET profiles`, `GET profiles/updates?since=`, `GET profiles/{userId}`;
- `ProfileDTO.kt`: `id: Long`, `type`, `status`, `badge`, `nowPlaying`, `deleted`, `canChangeBadge`, `number: Int`;
- `BadgeDTO.kt`: `documentId: Long`, `text: String?`;
- `BadgesController.kt`: `SUPPORTER_BADGE`, `DEV_BADGE`, `TRUSTED_BADGE`;
- `ApiBadgeSource.kt`: кэш профилей + синхронизация ~10 минут с ETag/`X-Sync-Timestamp`.

Прямой запрос к API из подготовчной среды не прошёл (`ECONNRESET`), поэтому поведение нужно
проверить на устройстве/в CI. Если сервер inaccessible — модуль просто не показывает бейдж.

## Что делает патч

- Запрашивает **только** публичный список: `GET /profiles` (без user id в URL).
- Отправляет `If-None-Match` при повторном запросе (через `WGNetworkRequest.etag`); ответ `304`
  оставляет предыдущий кэш.
- Парсит массив `ProfileDTO`; неизвестные поля игнорируются; `id` принимается числом или строкой.
- Хранит последний удачный ответ в `exteraBadge.cache` с флагом `.noExport` (не экспортируется,
  не попадает в бэкап настроек).
- Обновляет кэш не чаще раза в 600 секунд; кнопка «Обновить список бейджей» принудительно
  отправляет запрос.
- Ищет профиль по числовому Telegram user id. Если записи нет или `deleted == true` — бейдж
  не рисуется.

## Статусы

| `status` | Что показываем |
|---|---|
| `SUPPORTER` | `badge.text`, либо «SUPPORTER»; подпись «Саппортер exteraGram» |
| `DEVELOPER` | `badge.text`, либо «DEVELOPER»; подпись «Разработчик exteraGram» |
| `DEFAULT` / прочее | ничего |

`badge.documentId` сохраняется в DTO, но не используется для отрисовки: для загрузки реального
document-а нужен Telegram file-reference контекст, которого нет в layout-хуке. Патч честно
показывает **текст, который дал сервер**, а не поддельный графический бейдж. Если хотите точную
картинку — добавьте резолвер документов в слое Wraithgram и замените `WGExteraBadgePillView`.

## Приватность

- `WGNetwork` разрешает только `https`, не шлёт куки/телеметрию и идёт через SOCKS5-проки
  пользователя; при MTProxy/WEB-прокси запрос пропускается.
- В запрос не кладётся ни ID, ни токен, ни device info.
- Никаких локальных «прав» и белого списка: сервер — единственный источник истины.

## Проверка на устройстве

1. Открыть «Оформление › Профиль и Настройки › Профиль», включить «Бейджи exteraGram».
2. Нажать «Обновить список бейджей» (счётчик справа должен показать число профилей).
3. Открыть профиль, который точно есть в публичном списке, — должна появиться строка бейджа.
4. Если счётчик «—»: проверить сеть/прокси и доступность `api.exteragram.app`.
